# CLAUDE.md

A RAG demo over NASA's Astronomy Picture of the Day (APOD): ask an astronomy question,
get an answer grounded only in real APOD texts, with the source pictures and videos.
Sibling of `nuxt-nasa-cache`; both share a visual language and link to each other.

Stack: Nuxt 4 · Vue 3 · TypeScript (strict) · Tailwind 4 · shadcn-vue · Zod ·
Google Gemini · Upstash Vector · Netlify. Package manager **npm**, Node from `.nvmrc`.

## Commands

```bash
npm run dev        # dev server; restart after config, model or ingest changes
npm test           # vitest
npm run typecheck  # nuxi typecheck (vue-tsc), ~30s
npm run lint       # eslint (lint:fix to autofix)
npm run build      # production build
npm run ingest     # build or refresh the vector store, resumable
npm run eval       # offline retrieval check (Recall@K, MRR), needs Gemini quota
```

Husky: pre-commit runs lint-staged + `npm test`, pre-push runs `npm run typecheck`.
Netlify builds with `test && typecheck && build`, so a type error blocks the deploy.
`.env` needs `GEMINI_API_KEY`, `UPSTASH_VECTOR_REST_URL`, `UPSTASH_VECTOR_REST_TOKEN`.

## Architecture

Clean architecture on the server; dependencies point inward, the core never sees an SDK.

- `shared/contracts/ask.ts`: Zod schemas for the ask wire shapes, the single source of
  truth for those types. Controllers `.parse()` their responses; the client imports
  types only, so Zod stays out of the client bundle.
- `server/domain/`: entities (`ApodEntry`, ask types re-exported from the contract).
- `server/usecases/`: `resolveQuestion`, `suggestQueries`, `ingestApodRange`,
  `resolveApodPreview`, `resolveSharePreview`, `evaluateRetrieval`, plus `ports/`.
- `server/infrastructure/`: adapters for Gemini, Upstash and NASA that implement the
  ports. `config.ts` reads env once per composition root and injects it.
  `upstreamError.ts` turns SDK failures into one typed `UpstreamError` and owns retries.
- `server/api/`: thin controllers, the composition roots.
- One `ingestApodRange` use case drives both the full backfill and the daily function.

Query flow: optional "smart search" suggests cleaned-up questions (`/api/suggest`), the
chosen question is embedded, Upstash returns the top 5 by cosine, Gemini answers as
structured JSON with a `decision` of `answer`, `noMatch` or `nonsense`.

## UI conventions

- Dark only. Colours only through the tokens in `app/assets/css/tailwind.css`.
- Real Tailwind classes before arbitrary `[...]` values; repeated ones become `@utility`.
- All UI copy and per-page SEO come from `server/api/content.get.ts`, never hard-coded.
- Images through `@nuxt/image`. New remote hosts go into `app/utils/getImageConfig.ts`
  and `netlify.toml`.

## Gotchas

- NASA's legacy `api.nasa.gov/planetary/apod` answers 200 but returns the NASA logo for
  every date. The catalog reads `science.nasa.gov/wp-json/wp/v2/apod-basic`; its quirks
  are handled in `nasaApodCatalog.ts`.
- A high embedding score does not mean a sensible question: gibberish can outscore real
  questions. Gemini's `decision` separates them; `MIN_RETRIEVAL_SCORE` is only a
  pre-filter.
- Gemini free-tier models are often busy. `geminiModelFor` falls over to lighter models
  on 5xx; 429 is deliberately not retried. Model ids need a manual bump when a
  generation retires.
- After `npm run ingest`, restart dev: `embed.ts` caches its Gemini client.
- The sitemap is generated by `@nuxtjs/sitemap`; a `public/sitemap.xml` would shadow it.
  The site URL is hard-coded in `public/robots.txt`, `public/llms.txt`,
  `nuxt.config.ts` and `app/app.vue`; update all four on a domain change.
- The social preview only uses NASA-owned stills (no `copyright`), so it is often a week
  or two old. That is intended.
